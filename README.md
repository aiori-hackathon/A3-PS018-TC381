# HAPS Link-Quality Prediction Using a Documented Channel Model

**AIORI-3 Hackathon | Problem Statement: PS-018**

## 1. Project Overview

This project develops a simulation-based framework for predicting link quality between a High-Altitude Platform Station (HAPS) and a ground receiver.

The HAPS is positioned at an altitude of 20 km. The system uses a documented propagation model, link-budget calculations and machine-learning techniques to estimate received signal power and signal-to-noise ratio (SNR).

Two environmental scenarios are considered:

* Clear-air conditions.
* Rain-affected conditions.

## 2. System Configuration

The simulation uses the following parameters:

| Parameter             |       Value |
| --------------------- | ----------: |
| HAPS altitude         |       20 km |
| Operating frequency   |       2 GHz |
| Receiver height       |       1.5 m |
| Transmit power        |      30 dBm |
| Transmit antenna gain |      20 dBi |
| Receive antenna gain  |       5 dBi |
| Bandwidth             |      10 MHz |
| Noise figure          |        5 dB |
| Thermal noise density | -174 dBm/Hz |
| Earth radius          |     6371 km |

These values are simulation assumptions and are not measurements from a real HAPS deployment.

## 3. Propagation Model and Link Budget

### 3.1 Propagation Model

The project uses the ITU-R P.528-5 propagation model to calculate basic transmission loss.

The propagation module calculates path loss based on the selected frequency, HAPS altitude, receiver height and ground distance.

### 3.2 Geometry Calculations

The geometry module calculates:

* Ground distance.
* Slant range.
* Elevation angle.

### 3.3 Link-Budget Calculation

Received power is calculated using:

**Pr (dBm) = Pt + Gt + Gr - L**

Where:

* Pt = Transmit power.
* Gt = Transmit antenna gain.
* Gr = Receive antenna gain.
* L = Propagation path loss.

Receiver noise power is calculated using:

**N (dBm) = -174 + 10 log10(B) + NF**

Where:

* B = Bandwidth in Hz.
* NF = Receiver noise figure in dB.

Signal-to-noise ratio is calculated as:

**SNR (dB) = Pr - N**

## 4. Environmental Scenarios

Two environmental scenarios are included in the simulation.

### 4.1 Clear-Air Scenario

The baseline propagation loss is calculated using ITU-R P.528-5 without additional rain attenuation.

### 4.2 Rain-Affected Scenario

Rain-specific attenuation is calculated using the ITU-R P.838 model.

The simulation uses the following assumptions:

* Rainfall rate: 25 mm/hour.
* Rain-layer height: 5 km.
* Frequency: 2 GHz.
* Polarization: Vertical.

A simplified effective rain-path approximation is used to estimate additional attenuation.

This approximation is intended for scenario comparison and is not a complete atmospheric rain-path prediction model.

## 6. Machine-Learning Model

A Random Forest Regressor is implemented to predict received signal power,
with SNR retained as a secondary link-quality prediction.

### Input Features

* Ground distance.
* Slant range.
* Elevation angle.

### Target Variables

* Received signal power in dBm (primary PS-018 target).
* Signal-to-noise ratio (SNR) in dB (secondary target).

### Model Configuration

* Algorithm: Random Forest Regressor.
* Number of estimators: 100.
* Random state: 42.
* Validation: Leave-One-Group-Out cross-validation.

The trajectory ID is used as the grouping variable. This ensures that complete trajectories are held out during evaluation rather than randomly splitting individual samples from the same trajectory.

Separate models are evaluated for the clear-air and rain-affected scenarios.

## 7. Prediction Results

The model produced the following results:

| Scenario      | Samples | Trajectories | Received-power MAE | SNR MAE |
| ------------- | ------: | -----------: | ------------------: | -------: |
| Clear air     |     235 |            8 |          0.0134709 dB | 0.0137753 dB |
| Rain affected |     235 |            8 |          0.0130351 dB | 0.0136983 dB |

MAE represents Mean Absolute Error.

These values measure how closely the machine-learning predictions match the
synthetic analytical received-power and SNR reference values generated by the
simulation. They should not be interpreted as real-world prediction accuracy.

Prediction results are saved in:

`data/prediction_results.csv`

## 8. Analytical Baseline Comparison

## 9. Sensitivity Analysis

Sensitivity analysis is performed by varying individual link-budget parameters while keeping the P.528 reference path loss fixed at the model result for 50 km in clear air (approximately 133.06699 dB). Propagation sensitivities recompute path loss for each tested ground distance or environmental scenario.

| Parameter      | Tested Values  | Resulting SNR Values   |
| -------------- | -------------- | ---------------------- |
| Transmit power | 25, 30, 35 dBm | 15.86, 20.86, 25.86 dB |
| Transmit gain  | 15, 20, 25 dBi | 15.86, 20.86, 25.86 dB |
| Receive gain   | 0, 5, 10 dBi   | 15.86, 20.86, 25.86 dB |
| Bandwidth      | 5, 10, 20 MHz  | 23.87, 20.86, 17.85 dB |
| Noise figure   | 3, 5, 7 dB     | 22.86, 20.86, 18.86 dB |

The results show how changes in transmit power, antenna gains, bandwidth and receiver noise figure affect the calculated SNR.

Results are saved in:

`data/sensitivity_results.csv`

The reproducible sensitivity plot is saved in:

`data/sensitivity_analysis.png`

## 11. Installation and Setup

### Step 1: Clone the repository

```bash
git clone <repository-url>
cd A3-PS018-TC381
```

### Step 2: Create a virtual environment

```bash
python3 -m venv .venv
```

### Step 3: Activate the environment

```bash
source .venv/bin/activate
```

### Step 4: Install dependencies

```bash
pip install -r requirements.txt
```

The requirements file pins Py528 to the exact upstream Git commit that
provides the `Py528.P528.bt_loss` API used by this project. Git must therefore
be available when installing dependencies; the package is not published on
PyPI under the old `Py528==5.0.1` requirement.

## 12. Running the Project

Run the following commands from the project root directory.

### Generate the dataset

```bash
source .venv/bin/activate
python -m src.dataset_generator
```

This writes `data/haps_dataset.csv` using the documented trajectories and both environmental scenarios.

### Run the ML evaluation

```bash
source .venv/bin/activate
python -m src.ml_model
python -m src.baseline_comparison
```

The first command writes precomputed held-out predictions for received power
and SNR to `data/prediction_results.csv`; the second writes
`data/baseline_comparison.csv` and reports matching received-power and SNR MAE.
The evaluation uses `LeaveOneGroupOut` by `trajectory_id`. It is a synthetic
benchmark: trajectories overlap in ground-distance ranges, so the held-out
results are primarily interpolation within the modeled domain.

### Benchmark prediction time

```bash
source .venv/bin/activate
python -m src.inference_benchmark
```

This writes `data/inference_benchmark.csv`. It times repeated prediction-only
calls on held-out samples using `time.perf_counter()`; model loading and
training are excluded. Timing is environment- and run-dependent.

### Run sensitivity analysis

```bash
source .venv/bin/activate
python -m src.sensitivity_analysis
```

This writes `data/sensitivity_results.csv` and
`data/sensitivity_analysis.png`. The reference path loss is obtained directly
from P.528 at 50 km in clear air. Link-budget and propagation sensitivities are
stored separately with units and model provenance.

### Launch the interactive dashboard

```bash
source .venv/bin/activate
streamlit run app.py
```

Open the local URL printed by Streamlit, normally
`http://localhost:8501`. The dashboard uses the existing P.528 and P.838-based
helpers, checked-in analytical data, and precomputed ML predictions. It does
not retrain a model live. The rain result is a simplified effective-path
scenario comparison, not a complete atmospheric rain-path prediction.

### Run the full verification suite

```bash
source .venv/bin/activate
python -m pytest -ra
python -m pip check
```

The verified suite contains 36 tests. A clean run should report 36 passed and
no broken requirements.
